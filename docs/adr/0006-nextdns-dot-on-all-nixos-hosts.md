# NextDNS strict DoT via systemd-resolved on all NixOS hosts

Every NixOS host except warpe (gram, harpe, hector, pewter) imports `modules/system/config/resolved.nix`: systemd-resolved forwards all queries to the shared NextDNS profile (`7b9721`, threaded through `specialArgs` in `flake.nix`) over strict DNS-over-TLS — `DNSOverTLS = "yes"`, no plaintext fallback — using per-host endpoint names (`${host}-7b9721.dns.nextdns.io` as DoT SNI) so the console attributes traffic per machine within one profile. The driver was warpe: as a WSL guest it inherited the Windows-side corporate resolver in cleartext, and with pewter as exit node those query packets transited the tunnel just to reach work DNS. Harpe had the same shape; pewter itself resolved via Oracle's VCN resolver, unfiltered and visible to Oracle; gram already ran the module. The `~.` global routing domain is load-bearing, not decoration: NetworkManager/DHCP-learned resolvers rank above unscoped global config, so without it a host whose tailscaled is down silently leaks lookups to the router's plaintext resolver.

The layering principle this records: **an exit node forwards packets and never resolves names** — pewter carrying `resolved.nix` changes nothing for clients using it as an exit node, because each client resolves independently. Tailnet-wide policy therefore lives in two independent layers: the admin-console global nameserver with override local DNS (see 0006) covers devices that carry no local config — the iOS phone — while `resolved.nix` gives each standard host a path that survives tailscaled being stopped. Warpe is the exception per ADR-0012: the corporate network blocks NextDNS even over DoH, so warpe carries no local NextDNS path and resolves via the Windows-side resolver plus the MagicDNS split route. Consequences: resolution fails closed when TCP 853 is blocked (accepted trade of availability for confidentiality); LAN/mDNS names go unresolved, consistent with 0006; on harpe (the WSL guest carrying the module) the module is only live paired with `wsl.wslConf.network.generateResolvConf = false` (`modules/system/config/wsl/`), because while generation is on, upstream disables NixOS's `/etc/resolv.conf` entry and points the WSL-generated file at the Windows-side resolver — resolved runs but nothing queries it, which upstream flags in a warning for exactly this pairing. With generation off, resolved owns the stub symlink, lookups leave the Windows resolver stack entirely, and tailscaled stops hand-writing `resolv.conf` in favor of integrating through systemd-resolved like gram.

Considered and rejected: making pewter the tailnet resolver (console split-DNS or clients pointing at its tailnet IP) — an extra hop and a single point of failure for zero gain once every host self-resolves; relying solely on the console override — ties every host's DNS to tailscaled health and loses per-host endpoint attribution; leaving harpe/warpe on WSL default DNS — a plaintext corporate resolver behind an exit-node detour.
