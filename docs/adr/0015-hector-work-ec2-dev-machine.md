# hector is a tailnet-only Graviton EC2 NixOS dev machine isolated by tags, least-privilege instance profile, and work-host hardening

`warpe` needed a NixOS dev machine that `warpe` (WSL, split-DNS, `--accept-dns=false`) and `gram` can both `ssh` via tailnet, without interfering with coworkers' work-AWS resources or requiring `AdministratorAccess`. We add `hector` as an `aarch64-linux` Graviton EC2 host (`m7g.medium`, `80 GB gp3`, `us-east-1`) provisioned with `nixos-anywhere` + `disko` (no LUKS — EBS encryption at rest), tailnet-only after bootstrap, and an isolated `terraform/aws-hector/` local-state stack that owns only its SG/volume/instance/profile with `Owner=<work-username>` + `Project=hector` tagging and `DeleteOnTermination=true`. `hector` is a `Work host` (`CONTEXT.md: Hector isolation`) - its EBS `/dev/nvme0n1` and RAM can be snapshotted by work org admins via `SSM`/`ec2:CreateSnapshot`, so it is treated as `compromised-by-work-org` and hardens accordingly.

## Considered options

- **x86_64 (`m7i`/`t3`) vs Graviton (`m7g`/`t4g`)**: x86 avoids qemu for `amd64` container builds but costs ~15% more per vCPU; fleet already has `aarch64` (`pewter`) and Attic + remote builders cover cross, so Graviton wins on perf/price. Picked `m7g.medium` (1 vCPU/4 GB, `$0.0408/h` on-demand `us-east-1`) as cheapest Graviton general-purpose for cost minimization — `m7g.large` (2 vCPU/8 GB) was the prior perf pick, `t4g.medium` is similar but burstable and throttles sustained `nix build`.
- **LUKS vs EBS encryption**: `pewter` uses `disko` LUKS on raw block; on EC2 Nitro EBS is already encrypted at rest and `initrd.network.ssh` unlock adds friction with no benefit — dropped.
- **Public SSH vs tailnet-only**: tailnet-only removes SG exposure; temp public IP + `22` allowlist only for `nixos-anywhere`, then closed. SSM (`AmazonSSMManagedInstanceCore`) remains as fallback transport.
- **AdministratorAccess instance profile vs least-privilege**: `AdministratorAccess` (`*:*`) on a 24/7 instance profile is a fleet-wide breach if compromised and likely blocked by org SCPs. Least-privilege set (`AmazonSSMManagedInstanceCore` + `eks:CreateCluster/DescribeCluster` scoped to `arn:aws:eks:*:*:cluster/<team-prefix>*` + `iam:GetRole/ListInstanceProfiles` + `ec2:Describe*` + `ssm:StartSession` + `iam:PassRole` only to cluster roles) handles "create/manage clusters, inspect instance profiles, SSM into any instance" without admin; true admin is a separate assumable `hector-admin` role.
- **Shared `age` identity vs `Work host` no-key**: `docs/adr/0007` single `age14...vs8rs` `.sops.yaml:2` shared across all hosts would let EBS snapshot of `hector` (`/var/lib/sops-nix/keys.txt` `modules/system/config/sops.nix:18`) decrypt `secrets.yaml` (`oci_*`, `cloudflare_*`, `github_token`, `attic_jwt_secret`). Rejected. `hector` holds no shared `age` identity, `sops.nix` is not imported for `hector` (`flake.nix:104` `mkHostConfig` -> per-host imports for `gram`/`harpe`/`warpe`/`pewter` only), `nixos-anywhere --extra-files` does not copy `keys.txt` when building via `pewter` (`aarch64` `remoteBuilds` `modules/globals.nix:28`); future work-only secrets go in `secrets-hector.yaml` with a separate work-only `age` recipient never stored on `hector` (`docs/adr/0007:7` revisit trigger).
- **Tailscale flat `autogroup:member` mesh vs `tag:work` isolation + `isExitNode`**: `terraform/tailscale/main.tf:17` `acls: member->member:*` + `ssh check member->self` + `modules/globals.nix:31` `hector.isExitNode=true` would let `hector` reach `gram`/`harpe`/`pewter:22/8384` and advertise exit node to personal fleet. Rejected. `hector` is `tag:work` with `tagOwners`/`autoApprovers`, `isExitNode=false` (client only, no `--advertise-exit-node` `modules/system/config/tailscale/default.nix:27`), grants are `warpe`/`gram -> work:22` (for `nrs --target-host` `modules/hm/devenv/scripts/nrs.nix:41`) and `work -> pewter:443` (public `Attic` pull `cache.mippbipp.com/fleet`) + `work -> internet:*`, deny `work -> personal:22/8384/22000` and `work` `Tailscale SSH` to self only.
- **Attic push vs pull-only + `Syncthing`/`things`**: `hosts/pewter/attic.nix` push token and `things folder` `CONTEXT.md:158` `Syncthing` on `hector` would copy personal docs/credentials to work EBS. Rejected. `hector` `Attic` is pull-only (`nix.settings.substituters = https://cache.mippbipp.com/fleet` + `trusted-public-keys: fleet:6knX...` `modules/system/config/nix.nix:18` stays, no `attic_cache_token`/`attic_jwt_secret` `modules/system/config/sops.nix:26`), no `Syncthing`/`things`, deployments only via `nrs hector` from `warpe`/`pewter` (`--build-host root@pewter` avoids `warpe` `x86_64` qemu).
- **Tailscale `authKeyFile` persistence vs ephemeral tagged key**: `/var/lib/tailscale/authkey` (`hosts/hector/README.md:45` extra-files, `modules/system/config/tailscale/default.nix:28` `authKeyFile` only if `isExitNode`) left on disk would let snapshot enroll attacker node as `member` until expiry. Rejected. `hector` uses one-use `tag:work` `ephemeral=false` `reusable=false` `preauthorized` key, file deleted after first `tailscale status` + reboot uses `tailscaled.state`; re-bootstrap needs new key via `terraform/tailscale` `tailscale_tailnet_key`.
- **AuthorizedKeys scope + `company-root.pem`**: `hosts/hector/users.nix:23` `[gram.pubkey warpe.pubkey]` would keep personal `gram` `ed25519` on work EBS. Reduced to `[warpe.pubkey]` (deploy via `warpe`/`gram` `tailscale` `grants` still, but no personal pubkey material on disk). `hosts/warpe/work.nix` `company-root.pem` not installed on `hector` until `curl -vk https://channels.nixos.org` fails inside VPC.

## Consequences

- `flake.nix:104` `mkHostConfig` no longer imports `modules/system/config/sops.nix` globally; `hosts/gram|harpe|warpe|pewter/config.nix` import it per-host, `hosts/hector/config.nix` does not. `modules/globals.nix:31` `hector.isExitNode=false`, `hector` `authorizedKeys` is `warpe` only. `flake.nix:155` gets `hector = mkHostConfig`, `modules/globals.nix:14` gets `hosts.hector`, `.github/workflows/build-gate.yml:18` gets `hector` on `ubuntu-24.04-arm` and the `main` ruleset requires `build hector`. `nrs` from `warpe`/`gram` (`x86_64`) to `hector` uses `pewter`/`hector` remote builders (`aarch64` match avoids qemu).
- `terraform/tailscale/main.tf:17` `tailscale_acl` adds `tagOwners: {tag:work:[autogroup:member]}`/`autoApprovers` and `grants: warpe/gram->work:22`, `work->pewter:443` + `internet`, `nodeAttrs` unchanged `nextdns:7b9721`; `ssh check` narrowed to `tag:work` self. `hector` `authKeyFile` removed after bootstrap (`rm /var/lib/tailscale/authkey`), new joins use `tag:work` one-use key.
- `hosts/hector/config.nix` `nix.settings.substituters` keeps `https://cache.mippbipp.com/fleet` (pull-only, public `attic cache create --public`) + `trusted-public-keys`, no `sops` `attic_cache_token`/`github_token`/`oci_*`/`cloudflare_*` on `hector`; `things`/`Syncthing`/`Attic` daemon/`OCI`/`Cloudflare` providers excluded. Deployments are `nrs hector`/`nrs --push hector` from `warpe`/`pewter` via `tailscale` `grants`.
- AWS control plane stays out of `terraform/oci/`; `terraform/aws-hector/` is local state, gitignored, with its own `TF_VAR_*`, mirroring ADR 0011 isolation. No `company-root.pem` until `curl -vk https://channels.nixos.org` fails inside the VPC.
- Expansion is `aws ec2 modify-volume --size` + `btrfs filesystem resize max /`; `stop` keeps the 80 GB volume (pay storage), `terminate` is decommission only. Bootstrap roadblocks (`docs/agents/hector-roadblocks.md`) are disclosed behind a pointer — not inline in the host README. `CONTEXT.md: Hector isolation` gains `Work host`/`Personal host`/`Tag isolation` glossary.
