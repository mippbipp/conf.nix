# t3code from nixpkgs with provider flags

opencode stays on the llm-agents flake input (freshest build, used both as the CLI binary and driven by t3code), while t3code moves to nixpkgs' package overridden with `enableCodex = false; enableOpencode = true; opencode = <llm-agents opencode>`. llm-agents' t3code-desktop was dropped because it hard-bundles all five agent providers (`providerPackages`: grok, claude-code, codex, opencode, cursor-agent) with no opt-out, dragging a from-source Rust codex build into every rebuild; nixpkgs' t3code instead wraps only flag-enabled providers, so codex never evaluates. The `opencode` override keeps t3code driving the exact CLI binary (same store path) rather than a second nixpkgs build that would drift in version. nixpkgs' t3code still installs both the `t3` CLI and the `t3code-desktop` launcher; it lags llm-agents by a few releases, which self-heals as nixos-unstable propagates newer nixpkgs.

Considered and rejected: vendoring nixpkgs' t3code expression locally (hash-bump chore for every version with no freshness gain over the input), forking llm-agents to patch out codex (whole-flake maintenance), and substituting a codex stub into the override (t3code would still present codex as a provider), and enabling cursor via nixpkgs' `enableCursor`/`enableCursorCli` flags (unused in practice — dropped).
