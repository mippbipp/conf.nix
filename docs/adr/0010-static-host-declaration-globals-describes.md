# Hosts are declared statically in flake.nix; globals describes them

Centralizing hard-coded values into `modules/globals.nix` raised the question of whether the flake's `nixosConfigurations` should be *generated* from that same file — one registry, zero name duplication. The decision is a split: flake.nix keeps literal host declarations (`gram = mkHostConfig { host = "gram"; … }`), while globals carries everything another machine might need to know about an already-declared host. The rule of thumb: a line exists because *this* machine is something (uses `${host}`) or because it points *at* some other machine (reads Globals). Declaration sites are neither.

Generating outputs from the registry was considered and rejected: flake output attribute names must be static, so generation means `builtins.listToAttrs` over an imported file — the output shape of the top-level module becomes dependent on data it also depends on for descriptions, and tooling that statically reads `nixosConfigurations.*` (shell completion, CI matrices, `nrs <host>`) loses its anchor. For a four-host fleet the duplicated string per host buys back an evaluable, grep-able declaration surface. Consequences: adding a host touches exactly two files — flake.nix (declaration) and globals (record) — after which syncthing pairing, SSH peer blocks, authorized keys, exit-node selection, and remote-build flags derive themselves from the record.
